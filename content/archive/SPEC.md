# Разметка заметок архива «Шахматки»

Ты читаешь заметки инсайдерского Telegram-канала о недвижимости Москвы и превращаешь каждую в структурированную запись. Из записей потом автоматически собираются досье объектов (хронология событий по адресу участка), карточки застройщиков и лента «сигналов».

## Вход
JSONL-файл: одна строка — одна заметка `{"id", "date" (дата публикации, YYYY-MM-DD), "reply_to" (id заметки, на которую отвечает, или null), "text"}`.
В тексте встречаются ссылки вида `[Новая Басманная, 26](https://t.me/propertyinsider/21547)`: анкор — это обычно адрес участка или название проекта, а число в ссылке — id прошлой заметки о нём. Это сильная подсказка, о каком объекте речь.

## Выход
JSONL-файл: ровно одна строка на каждую входную заметку, в том же порядке, валидный JSON без комментариев:

```json
{"id": 21547,
 "kind": "news",
 "objects": [
   {"key": "Новая Басманная, 26", "name": "Демидов, 26", "aliases": ["усадьба Демидова"], "developer": "MR Group", "city": "Москва", "district": "Басманный", "role": "main"}
 ],
 "events": [
   {"obj": 0, "type": "deal", "date": "2024-01-25", "date_precision": "day", "title": "MR Group забирает участок с заброшенным корпусом больницы как мастер-девелопер", "certainty": "fact", "numbers": {}}
 ],
 "developers": ["MR Group"],
 "topics": ["земля", "больницы"],
 "refs_earlier": [14811],
 "confirms": [],
 "value": "brief"}
```

### Поля
- `kind`: `news` (событие), `analysis` (разбор, мнение, обзор рынка), `glossary` (объяснение термина), `listing` (перечень площадок/проектов), `poll`, `promo` (реклама, партнёрское, розыгрыш), `other`.
- `objects` — конкретные объекты недвижимости, о которых заметка (не упоминать абстрактные «рынок», «Москва»):
  - `key` — **адрес участка** в форме канала: «Улица, номер» («1-й Грайвороновский, 3», «Пресненский вал, 27», «Мосфильмовская, 74-78»). Без слов «ул.», «ЗУ», «ЖК», кавычек. Если адреса нет — `null`.
  - `name` — название проекта/ЖК без кавычек и без «ЖК» («Волжский парк»), иначе `null`.
  - `aliases` — другие названия из текста (старые, рабочие, варианты написания).
  - `developer` — застройщик или владелец участка, если назван (нормализуй: «ПИК», «Самолёт», «MR Group», «Level Group», «Эталон», «Гранель», «Донстрой», «ФСК», «А101», «Инград», «Sminex», «Stone», «Пионер», «ЛСР», «Брусника», «Галс», «Forma», «Glorax», «Hutton», «Coldy», «Tekta», «Мангазея», «Кортрос», «Sezar Group», «Ташир», «Абсолют», «Главстрой», «ДОМ.РФ»; прочих — как в тексте).
  - `city` («Москва», «Московская область», «Санкт-Петербург», другой город), `district` — район Москвы, только если назван или однозначно ясен из текста, иначе `null`.
  - `role`: `main` — заметка про этот объект; `mention` — упомянут для сравнения/контекста.
- `events` — что произошло с объектами (0–3 на заметку, только реальные события, не рассуждения):
  - `obj` — индекс объекта в `objects`.
  - `type`: `land` (покупка/продажа/аренда участка, ГПЗУ, ВРИ), `krt` (КРТ: включение, договор, торги), `concept` (концепция, ГЗК, градсовет), `architecture` (АГР, проект бюро, визуализации), `permit` (разрешение на строительство), `sales` (офис продаж, старт продаж, итоги продаж), `price` (цены, скидки), `deal` (сделка с компанией/проектом, смена девелопера), `construction` (снос, стройка, ввод), `court` (суд, иск, банкротство, проверки), `tender` (тендер, аукцион), `other`.
  - `date` — дата события, если в тексте указана; иначе дата заметки. `date_precision`: `day`, `month`, `year`, `note` (взята дата заметки).
  - `title` — одна фраза до 140 знаков, нейтральный деловой русский язык, без мата, жаргона и иронии, без упоминания канала, Telegram, «мы писали». Цифры и названия сохраняй точно.
  - `certainty`: `fact` (произошло: документ, сделка, старт продаж, решение), `signal` (кулуарная информация, планы, «присматриваются», «по слухам», «готовят», «скорее всего»), `forecast` (прогноз/мнение автора).
  - `numbers` — только явно названные в тексте: `price_m2_rub` (руб. за м²), `price_from_rub`, `area_m2` (площадь застройки/квартир, м²), `land_ha`, `floors`, `height_m`, `apartments`, `deals` (число сделок), `sum_rub` (сумма сделки). Тысячи и миллионы переводи в рубли числом: «165 тыс. руб./кв. м» → 165000; «4,6 млн» → 4600000.
- `developers` — все застройщики/компании, о которых заметка (нормализованные).
- `topics` — 1–4 темы из списка: земля, КРТ, ГЗК, архитектура, разрешения, старт продаж, цены, ипотека, ставка, эскроу, сделки, суды, банкротства, реновация, апартаменты, коммерческая, офисы, ОКН, градозащита, регионы, Подмосковье, Петербург, рынок, застройщики, госполитика, больницы, промзоны, транспорт.
- `refs_earlier` — id заметок из ссылок `t.me/propertyinsider/ID` в тексте (числа).
- `confirms` — id тех заметок из `refs_earlier`, чьё предположение/слух эта заметка **подтверждает** (маркеры: «как и предполагалось», «как мы писали», «подтвердилось», «наконец», «теперь официально»). Иначе `[]`.
- `value`: `article` (самостоятельная ценная история: событие с деталями, большой разбор, эксклюзив — достойна отдельной статьи), `brief` (короткий факт — пункт хронологии объекта), `skip` (шутка, мем, реплика без фактов, опрос, реклама, дубль).

## Правила
- Только то, что есть в тексте. Не додумывай адреса, районы, застройщиков, даты.
- Одна заметка может быть про несколько объектов (перечни площадок): выпиши до 10 главных, для перечней событие можно не создавать.
- Старое название канала и его хэштеги в выход не попадают.
- Обрабатывай все заметки файла, ни одной не пропускай; порядок — как во входе.
