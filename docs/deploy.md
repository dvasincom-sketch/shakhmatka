# Деплой Шахматки на Timeweb Cloud Apps

Сайт собирается из `Dockerfile` в корне репозитория. В контейнере ничего не хранится между деплоями,
поэтому база — управляемый PostgreSQL, фото — S3-хранилище Timeweb.

## Что создать в Timeweb (один раз)

1. **База данных → PostgreSQL** (16). Запомнить хост, порт, пользователя, пароль, имя базы.
   Если приложение и база в одной приватной сети — использовать приватный адрес базы.
2. **S3-хранилище → бакет** (приватный). Ключи доступа — в настройках хранилища.
3. **App Platform → Backend → Dockerfile**, репозиторий `dvasincom-sketch/shakhmatka`, ветка `main`,
   путь до директории проекта — пустой (корень), путь проверки состояния — `/healthz/`.
   Приватную сеть выбрать сразу (потом её не поменять) — ту же, что у базы.

## Переменные приложения

| Переменная | Значение |
| --- | --- |
| `DATABASE_URI` | `postgres://user:password@host:5432/db` |
| `DATABASE_SSL` | `1`, если база требует SSL (для публичного адреса Timeweb — обычно да) |
| `PAYLOAD_SECRET` | длинная случайная строка (`openssl rand -hex 32`), не менять после запуска |
| `S3_BUCKET` | имя бакета |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | ключи S3 |
| `S3_ENDPOINT` / `S3_REGION` | `https://s3.twcstorage.ru` / `ru-1` (значения по умолчанию) |
| `NEXT_PUBLIC_SITE_URL` | `https://шахматка.москва` (по умолчанию) |
| `PUBLIC_ROBOTS` | `1` — только когда сайт готов к индексации на боевом домене |
| `SEED_ON_START` | `1` на первый деплой, потом `0` |

## Первый запуск

1. Деплой с `SEED_ON_START=1`: при старте применяются миграции базы, сайт поднимается,
   в фоне импортируются статьи, районы, факты, досье (≈1–2 мин) и словарь. Лог — вкладка «Деплой» / «Логи».
2. Сразу открыть `/admin/` и создать первого администратора (пока его нет, создать может любой).
3. Опубликовать термины словаря в админке (импорт создаёт их черновиками).
4. Поставить `SEED_ON_START=0` и перезапустить: иначе каждый деплой будет перезаписывать статьи из `content/`
   поверх правок в админке. Досье с галочкой «Собрано из архива» перезаписываются всегда, ручные — нет.
5. Привязать домен шахматка.москва (A-запись на IP приложения), SSL Let's Encrypt выпускается автоматически.
6. Когда всё проверено — `PUBLIC_ROBOTS=1`.

## Обновления

- Код: `git push` в `main` → автодеплой. Миграции применяются при старте.
- Изменили коллекции (поля) — перед коммитом создать миграцию (нужен локальный PostgreSQL):
  `DATABASE_URI=postgres://… npx payload migrate:create имя` → закоммитить `web/src/migrations/`.
- Новый контент из `content/` (статьи, досье): закоммитить и один деплой с `SEED_ON_START=1`.

## Локально

Без `DATABASE_URI` сайт работает на SQLite-файле `web/shakhmatka.db`, схема подтягивается сама, фото — в `web/media/`.

## Поиск (Meilisearch)

**Ничего настраивать не нужно.** Meilisearch встроен в Docker-образ сайта: при старте контейнер сам запускает его на 127.0.0.1:7700 со случайным ключом, собирает индекс (несколько секунд) и включает подсказки в шапке и поиск на /poisk/. В логе: `→ поиск: встроенный Meilisearch` и `✓ поиск: индекс «shakhmatka» … — N документов`.
Индекс живёт внутри контейнера и пересобирается при каждом старте; правки в админке попадают в него сразу.

Переменные (необязательно):
- `MEILI_EMBEDDED=0` — не запускать встроенный (сайт будет искать по базе).
- `MEILI_HOST` + `MEILI_MASTER_KEY` — использовать внешний Meilisearch (отдельное приложение Timeweb из образа `getmeili/meilisearch:v1.12`); тогда встроенный не запускается.
