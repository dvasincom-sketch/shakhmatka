# Спорные районы объектов — проверка по источникам (бриф)

Вход: `/home/claude/pipeline/districts-fill/resolve-in.json` — 82 объекта Москвы. У 79 две разметки разошлись (`variant_a`, `variant_b` с доказательствами), у трёх район в досье под сомнением (`current_district`). Допустимые ключи районов — `/home/claude/pipeline/districts-fill/districts-list.txt`.

Задача: для каждого определить район Москвы по внешнему источнику с адресом: карточка ЖК/участка на novostroy-m.ru, cian.ru, сайт застройщика, mos.ru (решения ГЗК, КРТ, Москомархитектура), публичная кадастровая карта в выдаче, деловые СМИ. В источнике должен быть **адрес с номером дома или прямо назван район**.
- Бюджет: **не больше 1 WebSearch на объект и 45 WebSearch всего**, WebFetch — только адреса из выдачи, не больше 1 на объект. Часто район виден прямо в сниппете выдачи (карточки ЖК пишут «район Даниловский, ЮАО»).
- Сначала объекты с конкретным адресом (`zu` или адрес в названии/заметках), потом остальные. Когда 45 поисков кончились — оставшимся `district: null, reason: "не проверено"`.
- Ключ района — только из списка. Объект не в Москве — `region` (slug региона), `district: null`.
- Не угадывай: нет источника с адресом/районом — `district: null`.

Выход: `/home/claude/pipeline/districts-fill/resolve-out.json` — массив `{"slug", "district" | null, "region": null | "...", "source": "URL", "evidence": "что именно в источнике (адрес/район)"}` на каждый входной объект.

Ответ мне: сколько определено по источнику, сколько не определено, сколько поисков. Одной-двумя строками.
